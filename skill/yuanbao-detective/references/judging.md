# 判断规则（第 3 步）

## 铁律

1. 只依据第 2 步输出的编号摘录作答，**绝不用自己的记忆补充事实**。你记得的答案不算证据，摘录里没有的就是“没查到”。
2. `evidence` 里每条 `quote` 必须从摘录里**逐字复制**，不改写、不缩写、不合并两句；`id` 就是摘录编号。脚本会逐字核对，对不上的会被标红，不算依据。每条不超过 60 字。
3. 只提到人物、角色或作品，却没谈到这个具体点的摘录，不能当证据。
4. `summary` 先给结论，再给关键依据，关键处用 `[编号]` 标出处。要写得让完全不懂这个领域的人也能看懂。
5. 百科是正常可用的来源，不要说它们“可信度有限”。只有当关键证据主要来自同人创作、语录站、问答站、内容农场时，才在 `caveat` 里提醒。其余情况下，`caveat` 写还没查到的部分，或者留空。

## 评级

**说法（type = claim）**
| verdict | 什么时候用 |
|---|---|
| 有出处 | 有原句直接说明了这件事，并且和说法一致 |
| 说法有偷换 | 有原句谈到相关内容，但意思不同：偷换概念、断章取义、张冠李戴、改字、把个人习惯说成通用规则 |
| 说法有分歧 | 不同摘录互相矛盾，或者这件事属于还没有定论的争议 |
| 查不到 | 没有摘录直接谈到这个具体点 |

**问题（type = question）**
| verdict | 什么时候用 |
|---|---|
| 查到答案 | 摘录足以回答这个问题 |
| 部分查到 | 只能回答一部分，要写明哪部分没查到 |
| 来源有分歧 | 不同摘录给出互相矛盾的答案，要分别列出 |
| 查不到 | 没有摘录能回答这个问题 |

脚本另外会自动给出一档 **社区说法**：你判了“有出处/查到答案”，但支持它的原句全部来自论坛或同人站时，自动降到这一档。

## 字段

- `true_points`：原文能证实的点，每条带 `cite`
- `false_points`：原文能证伪的点，或者流传说法和原文不符的地方，每条带 `cite`
- `unknown_points`：摘录里查不到的点（字符串列表）
- `warrant`：一句话说明，为什么这些证据能推出这个结论（Toulmin 论证模型里的“依据”）
- `evidence[].stance`：`支持`、`反驳`、`相关` 三选一，是相对于用户原话而言的
- `need_clues`：结论为「查不到」或「部分查到」时必填，写明需要用户提供哪类线索，例如「在哪里看到的」「是漫画还是动画」「原文措辞」

## 补搜策略（第 ⑤ 步）

| 诊断结果 | 现象 | 先用的策略 |
|---|---|---|
| 搜索词不对（terms_miss） | 网页很多，但几乎没有一页提到细节词 | **换说法**：同义词、原文语言（日文、英文、文言）、原文里的叫法 |
| | | **放宽**：去掉限定词 |
| 来源太弱（weak_sources） | 提到细节的只有论坛、问答站 | **权威源**：在 `sites` 里填权威站点，做站内搜索 |
| | | **反向**：搜「辟谣」「误传」「不是」 |
| 已有细节（has_detail） | 权威来源谈到了，但答不上 | **顺藤摸瓜**：用原句里出现的新书名、篇名、人名、章节名再搜 |

- 每轮 1 到 4 条新搜索词，`add_terms` 写新增的细节短词。
- 最多补到第 3 轮。上一轮没带来新网页就停。

## 手工规则（不能运行 Python 时）

**摘句**
1. 每个结果取 `title + content`；没有 content 就用 passage。
2. 在文本里找每个细节词，取它前 90 字到后 130 字的范围，再按句号截齐；相邻的范围合并；每个网页最多取 3 段。
3. 一段细节词都没命中的网页，丢掉，不进入判断。
4. 内容完全相同的镜像站，只留一个。
5. 排序和编号：按「命中细节词的个数 × 来源权重」排序。来源权重为：官方 3、百科 2、媒体或社区 1.2、其他 1、问答农场 0.4。取前 14 个，编号 [1] 到 [14]。

**核对**：判断写完后，逐条检查 quote 是否一字不差地出现在对应编号的摘录里，对不上的标「原文找不到」，不算依据。

**降级**：判了「有出处/查到答案」，但支持它的原句全部来自论坛或同人站时，改判「社区说法」。

**出报告**：版式照 `report-template.md`。查不到时，加两段：「试过的搜索」和「需要你提供的线索」。
